OpenClaw agent 是怎么出生的

2026-05-13
技术共享
凯风自南，吹彼棘心。

这篇文章写给没有 IT 背景的人。它讲：怎样在一台普通 Windows 电脑上部署一个本地 AI Agent。我的 agent 叫 Anna。

一、先理解 Agent 是什么

Agent 不是 ChatGPT 网页里的一个聊天窗口。她是一个运行在本地电脑上的连接着大语言模型的程序。OpenClaw 负责把大模型、聊天入口、本地文件、命令行、浏览器、定时任务和长期记忆接在一起。

普通网页版 AI 主要回答问题。OpenClaw agent 可以在你允许的范围内执行任务：

  • 读指定文件；
  • 写指定文件；
  • 跑测试和脚本；
  • 修改网站项目；
  • 检查错误；
  • 记录任务状态；
  • 在批准后部署或推送代码。

二、准备电脑环境

我的路线是：

Windows 电脑
+ WSL2 Ubuntu
+ OpenClaw
+ 模型供应商
+ 一个安全工作区
+ 一个聊天入口

你需要准备：

项目用途
Windows 电脑主机
WSL2 Ubuntu运行 OpenClaw
OpenAI / OpenAI Codex 等模型给 agent 调用模型
GitHub 账号放网站代码，可选
Cloudflare / Vercel部署网站，可选
Telegram / WhatsApp / Discord和 agent 聊天，可选
安全工作区限制 agent 的文件操作范围

注意：ChatGPT Plus 不等于 OpenAI API 额度。ChatGPT 网页订阅和 OpenAI Platform API 是两套计费。OpenAI Codex 登录、OpenAI API key、Gemini、Claude、OpenRouter 等 provider 也要分清。

三、安装 WSL2 Ubuntu

打开 Windows PowerShell 管理员模式，输入：

wsl --install -d Ubuntu-24.04

安装完后：

  1. 重启电脑；
  2. 开始菜单搜索 Ubuntu 24.04 LTS；
  3. 第一次打开时设置 Linux 用户名和密码；
  4. 看到类似下面的提示，说明成功：
yourname@DESKTOP-XXXX:~$

以后进入 Ubuntu，可以在 PowerShell 输入：

wsl -d Ubuntu-24.04

查看已安装的 Linux：

wsl -l -v

关闭所有 WSL：

wsl --shutdown

后面的命令，除非特别说明，都在 Ubuntu 里执行。

四、安装 OpenClaw

在 Ubuntu 里执行：

curl -fsSL https://openclaw.ai/install.sh | bash

如果安装后没有自动进入设置流程，继续执行：

openclaw onboard --install-daemon

--install-daemon 的意思是让 OpenClaw 作为后台服务运行，不必每次手动启动。

安装后先检查：

openclaw gateway status
openclaw doctor

如果 gateway 没启动，可以用：

openclaw gateway restart

五、配置模型供应商

OpenClaw 会问你使用哪个 provider。常见选择是：

方案说明适合
OpenAI Codex用 ChatGPT / Codex 登录能力本地 coding、改项目、跑测试
OpenAI API用 OpenAI Platform API key长期自动化、可控计费
Gemini / Claude / DeepSeek / OpenRouter其他模型供应商fallback 或不同任务
Ollama / LM Studio本地模型低风险文件初筛

最简单的起步路线：

先用 OpenAI Codex 跑起来。
后面再加 OpenAI API key 或其他 provider。

如果要添加或修改 provider：

openclaw configure

查看模型：

openclaw models status
openclaw models list --all

设置默认模型：

openclaw models set openai-codex/gpt-5.5

如果模型名不存在，先用 openclaw models list --all 看实际名称，再复制进去。

在聊天里临时切模型，可以发：

/model list
/model openai-codex/gpt-5.5
/model status

六、如果使用 OpenAI API key

如果你选择 OpenAI API：

  1. 打开：https://platform.openai.com/
  2. 进入 API Keys 页面；
  3. 创建新的 secret key；
  4. 确认 billing 已设置。

API key 只显示一次。不要发给别人，不要贴进网页、GitHub、截图或聊天记录。

在 Ubuntu 里写入环境变量：

nano ~/.bashrc

在文件末尾添加：

export OPENAI_API_KEY="你的_API_KEY"

保存：

Ctrl + O
Enter
Ctrl + X

刷新：

source ~/.bashrc

检查变量是否存在：

echo $OPENAI_API_KEY

能看到值，说明写入成功。正式文章或截图里不要展示这个值。

七、建立安全工作区

先不要让 agent 扫描整个电脑。

我给 Anna 的工作区是：

你的安全工作区

你也可以用其他盘，例如：

你的安全工作区

建议结构：

安全工作区
├── Inbox
├── Products
├── Backup
├── Sorted
├── Review_To_Delete
├── Logs
└── Temp

规则很简单：

  1. 只把可以给 AI 处理的副本放进工作区；
  2. 不让它直接碰 Desktop、Downloads、Documents、客户原件；
  3. 删除不是真删除，只能移动到 Review_To_Delete；
  4. 批量移动、重命名、覆盖前必须先列操作表；
  5. 所有文件操作写日志。

八、写 Anna 的身份文件

OpenClaw agent 需要长期说明文件。它们像出生证明、家规和工作手册。

常见文件：

AGENTS.md
SOUL.md
USER.md
TOOLS.md
MEMORY.md
HEARTBEAT.md

大致作用：

文件作用
AGENTS.md总规则、工作方式
SOUL.md角色、语气、边界、长期偏好
USER.md用户基本信息
TOOLS.md本地工具、路径、设备说明
MEMORY.md长期记忆
HEARTBEAT.md周期性检查任务

给 Anna 的最小身份说明可以这样写：

Your name is Anna.
You are my private local operations assistant.

You help me with:
- file organisation;
- blog maintenance;
- coding support;
- compliant web research;
- workflow automation.

Style:
- concise;
- organised;
- evidence-aware;
- practical;
- no unnecessary humour;
- ask before risky actions.

Hard rules:
1. Never permanently delete files.
2. Move deletion candidates to Review_To_Delete.
3. Do not modify files outside approved workspaces.
4. Ask before external publication, deployment, email, DNS, account, or secret changes.
5. For batch file operations, show an action table and wait for approval.
6. Do not access legal client files unless copies are placed in the approved workspace.
7. If unsure, stop and ask.

这一步很重要。不要靠每次聊天临时提醒它。长期规则应该写进文件。

九、连接聊天入口

OpenClaw 可以接不同聊天入口。以 WhatsApp 为例：

openclaw channels login --channel whatsapp

终端会显示 QR code。

手机操作：

WhatsApp
→ Settings
→ Linked devices
→ Link a device
→ 扫终端里的 QR code

检查 channel：

openclaw channels status --probe

如果 gateway 没跑：

openclaw gateway status
openclaw gateway restart

然后从手机给 Anna 发测试消息：

Reply exactly: Anna connected.

如果她能回复，说明聊天入口打通。

十、第一次安全测试

不要一上来让 Anna 整理全盘文件。

先放几个测试文件到：

你的安全工作区

然后发：

请只读扫描 你的安全工作区。不要移动、删除、重命名或修改任何文件。只输出：
1. 文件总数；
2. 按扩展名分类；
3. 可能的主题分类；
4. 建议文件夹结构；
5. 需要我确认后才能执行的操作清单。

如果这一步稳定，再允许它移动测试文件到 Sorted。

不要给永久删除权限。

十一、让 Anna 会记事

没有记忆的 agent 会反复问同样问题。

Anna 的日常记忆可以放在：

memory/YYYY-MM-DD.md

长期记忆整理到：

MEMORY.md

记忆不是聊天记录全集，而是可复用事实，例如：

T001是判决网页爬虫项目
T002 是博客建设和维护项目。
T003 是移民咨询网站建设和维护项目。
批量文件操作必须先列操作表。
C 盘普通路径不能随便访问。

推荐规则：

  1. 当用户说“记住”，写进记忆；
  2. 当一个任务跨天，写进记忆；
  3. 当发生错误并修复，写进记忆；
  4. 当形成可复用流程，写进记忆；
  5. 不把密码、API key、客户资料写进记忆。

十二、给 Anna 一个小任务

初始设置一个很小、边界清楚的项目。例如：

在 你的安全工作区创建一个本地 Markdown 博客。
只生成本地文件。
不要部署。
不要推送 GitHub。
完成后告诉我文件清单和预览方式。

如果要让她搭博客，可以分阶段：

阶段 1：只创建本地项目。
阶段 2：本地 build 和预览。
阶段 3：创建 GitHub repo。
阶段 4：部署到 Cloudflare / Vercel。
阶段 5：设置自动同步。

每一阶段都要有验证：

npm run build
npm run check
curl -I 本地或线上地址

不要让一个刚出生的 agent 直接改 DNS、发邮件、发帖、批量移动文件或处理客户材料。

十三、常用维护命令

查看 OpenClaw 状态：

openclaw status
openclaw gateway status
openclaw doctor

查看 channel：

openclaw channels status --probe

配置模型：

openclaw models status
openclaw models list --all
openclaw models set provider/model

重新配置：

openclaw configure

安全检查：

openclaw security audit

如果要看帮助：

openclaw help
openclaw gateway --help

十四、Anna 是怎么出生的

Windows
→ WSL2 Ubuntu
→ OpenClaw
→ 模型 provider
→ 安全工作区
→ 身份文件
→ 聊天入口
→ 只读测试
→ 小型本地项目
→ 记忆文件
→ 更复杂任务
